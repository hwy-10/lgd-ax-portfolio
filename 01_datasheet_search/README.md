# 데이터시트 검색 도구

USB 허브 보드(modulino)를 설계하면서 여러 부품의 사양을 한 번에 조사하고 실제 설계에 활용하기 위해 만든 도구입니다. 언어모델이 그럴듯한 답을 지어내는 할루시네이션을 피하는 데 중점을 두고 구현했습니다.

첫 문서는 허브 컨트롤러의 데이터시트(`CH334_CH335_V2.5.pdf`, 32쪽)였습니다. 한 권에 CH334U, CH334R, CH334Q, CH335P 처럼 접미사만 다른 변종 10종이 함께 실려 있어 찾은 내용이 질문한 품번에 해당하는지 구분해야 했습니다. 같은 방식을 보드의 다른 부품으로 넓혀 지금은 데이터시트 5권을 다룹니다.

답변하지 않을 조건을 먼저 정하고 그 조건을 통과한 경우에만 언어모델을 호출합니다.

| 범위 | 내용 | 평가 |
|---|---|---|
| CH334 한 권 | 처음 만든 범위. 기준값을 정한 문서 | `evaluate.py`, `calibrate.py`, `evaluate_answers.py` |
| modulino 부품 전체 (문서 5권) | 문서를 먼저 고른 뒤 해당 문서 안에서 찾습니다. 회로 기호(U5)는 BOM에서 품번을 찾습니다 | `evaluate_catalog.py`, 등록 절차는 [docs/EXTENDING.md](docs/EXTENDING.md) |

```
질문 ─▶ ① 품번 추출 ─▶ ② 변종 게이트 ─▶ ③ BM25 검색 ─▶ ④ 검증 게이트 ─▶ ⑤ 근거 충분성 ─▶ ⑥ 모델 호출 ─▶ ⑦ 원문 대조
                     다른 변종만 적힌      품번은 빼고        질문한 품번이      1위 점수와          통과한 경우만     인용 페이지와
                     청크를 뺍니다        내용으로 순위      문서에 있는지      용어 등장 비율                       수치를 원문과 대조
```

설치 없이 결과만 보시려면 ZIP 맨 위의 `시연.html`을 열어 주세요.

가상환경을 만들고 패키지를 설치한 뒤 브라우저에서 `http://localhost:8501`을 엽니다. 처음 실행할 때는 몇 분 정도 걸립니다.

- 가상환경은 `%LOCALAPPDATA%\lgd_ax_venv`에 만듭니다. 압축을 깊은 폴더에 풀어도 Windows 경로 길이 제한(260자)에 걸리지 않도록 하기 위한 설정입니다. 다른 위치를 사용하려면 실행 전에 `set LGD_AX_VENV=경로`를 지정해 주세요
- 화면 왼쪽에서 범위(CH334 한 권, 부품 전체)를 선택합니다. 부품 전체에서는 문서를 켜고 끌 수 있으며 한 권만 켜면 품번 없이 질문해도 해당 문서에서 찾습니다
- 클라우드 모델은 `pip install -r requirements-optional.txt` 후 `.env`에 `OPENAI_API_KEY` 또는 `ANTHROPIC_API_KEY`를 넣고 모델 이름을 바꾸면 같은 기준과 평가셋으로 실행할 수 있습니다

## 설계 결정

**BM25를 사용한 이유**

임베딩 토크나이저는 `CH334U`를 `[CH][334][U]`로 나누므로 `CH334R`과 세 토큰 중 하나만 다르게 봅니다. 한 글자 차이로 부품이 달라지는 문서이므로 품번형 토큰은 문자 n-gram으로 따로 색인해 정확히 구분합니다 (`src/lexical.py`).

**품번을 순위에서 제외한 이유**

품번 n-gram이 점수를 크게 끌어올려 품번이 적힌 핀 표가 질문 내용과 관계없이 상위에 올랐습니다. “CH334U 동작 전압”을 검색했을 때 품번이 적히지 않은 전기적 특성 표(p.21)가 나오지 않았습니다. 어느 품번의 근거인지는 ②④ 게이트에서 확인하고 순위는 내용으로 매깁니다. 품번을 명시한 근거 하나는 항상 남깁니다 (`src/pipeline.content_query`, `src/hybrid.HybridIndex.search`).

**점수만으로 차단하지 않는 이유**

“CH334U는 AEC-Q100 인증을 받았는가”의 BM25 1위 점수는 12.5로 정답이 있는 질문의 최저 점수(4.9)보다 높습니다. 따라서 점수만으로는 차단할 수 없습니다. 질문 용어가 근거에 실제로 등장하는 비율은 정답 질문이 모두 1.00이고 문서에 없는 질문은 최고 0.33으로 나뉩니다. `calibrate.py`는 그 사이인 0.67을 기준값으로 정했고 점수 기준(2.5)은 보조로 사용합니다.

**한국어 용어 표를 사용하는 이유**

문서는 영문이고 질문은 한국어입니다. 번역 모델 대신 표(`src/glossary.py`)로 변환해 같은 질문이 항상 같은 질의가 되도록 했습니다. 어떤 단어가 어떻게 바뀌었는지도 화면에 그대로 표시됩니다.

**답변을 다시 대조하는 이유**

모델에 근거 안에서만 답하라고 지시해도 지켰는지는 별도로 확인해야 합니다. 답변의 `[p.N]`이 실제로 전달한 근거 페이지인지, 단위가 붙은 수치가 근거 원문에 있는지 문자열로 검사합니다 (`src/answer_check.py`).

## 한계

- CH334 한 권 범위의 품번 패턴(`영문 2~5자 + 숫자 2자 이상 + 접미사`)은 주변 부품(CH213K, CH412K)과 패키지 코드(QFN16C)도 품번으로 인식합니다. 13종 가운데 CH334/CH335 변종은 10종입니다. 이 때문에 해당 부품만 적힌 응용 회로 청크도 변종 게이트에서 제외됩니다. 문서별 변종 규칙을 사용하는 부품 전체 범위에서는 이 문제가 없습니다
- 기준값은 CH334 38문항으로 정했습니다(기준값을 정한 셋과 잰 셋이 같습니다). TI 문서 4권에는 다시 맞추지 않고 그대로 적용해 확인했지만 문서와 질문 유형이 늘어나면 다시 확인해야 합니다
- 원문 대조는 사실 검증이 아닙니다. 인용 페이지가 전달한 근거에 포함되는지, 단위가 붙은 수치가 근거에 있는지 (부호 포함), 답변과 거절 문장이 섞이지 않았는지만 확인합니다. 같은 표의 다른 행 값을 가져온 경우는 찾지 못하므로 평가에서는 정답 사실의 포함 여부를 별도로 채점합니다
- 비교 질문(두 품번, 두 부품)에는 답하지 않습니다
- 핀 배치도와 회로도는 PDF 텍스트 추출 과정에서 순서가 깨집니다. TI 데이터시트 1쪽 기능 목록의 요약 값도 조건별 표에 밀려 근거로 가져오지 못하는 경우가 있습니다. 표와 목록 구조를 보존하는 파서가 다음 단계입니다
- 평가 질문은 직접 작성했습니다. 정답의 원문 위치를 함께 적어 검수할 수 있도록 했습니다. 외부 검토(GPT)에서 재현된 결함은 `tests/regression_questions.json`에 회귀 테스트로 남겼습니다

## 파일

```
app.py                  시연 화면 (Streamlit)
src/pipeline.py         질문부터 답변까지, 단계별 판정을 Trace 로 남김
src/variants.py         품번 추출, 변종 게이트 판정
src/lexical.py          문자 n-gram BM25
src/hybrid.py           게이트와 검증 게이트, 순위 융합
src/glossary.py         한국어 기술 용어 -> 영문
src/evidence.py         근거 충분성 판정
src/answer_check.py     답변 원문 대조
src/llm.py              OpenAI / Anthropic / 로컬(Ollama) 호출을 같은 형태로
src/catalog.py          부품 전체 범위: BOM 읽기, 문서 선택, 문서별 변종 규칙
src/prompt.py           지시문과 근거 블록
data/catalog.json       등록 문서와 변종 규칙
data/datasheets/        TI 데이터시트 4권 (TPS2552, LMR33630, TPS7A20, LM66100)
evaluate.py             변종 게이트 전수 검사
calibrate.py            기준값 결정
evaluate_answers.py     모델 비교
tests/                  단위 테스트, evaluation_questions.json (평가셋 38문항, 정답 출처 페이지 포함)
results/                검증 결과
tools/export_demo.py    시연.html 생성 (틀은 tools/demo_template.html)
src/retriever.py, src/ingest.py, src/embeddings.py
                        선택 경로: 임베딩 + ChromaDB (requirements-optional.txt). 기본 검색에는 쓰지 않음
```

페이지 번호는 PDF 파일의 쪽 번호입니다. 데이터시트 하단에 인쇄된 번호보다 1 큽니다.
