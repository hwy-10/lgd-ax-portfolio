온라인 보기: [시연 화면](https://hwy-10.github.io/lgd-ax-portfolio/%EC%8B%9C%EC%97%B0.html), [3부 문서 관리](https://hwy-10.github.io/lgd-ax-portfolio/03_local_docs/index.html)

### 시연 보는 법 (약 5분)

`시연.html` 위쪽 탭 순서대로 봐 주시면 됩니다.

**1. `1부 질문하기` 탭 (2분)**

시나리오 버튼을 누르면 모델을 부르기 전까지의 판정이 1~6단계 카드로 나옵니다. 카드마다 왼쪽의 통과, 차단 표시를 보시면 됩니다.

| 버튼 | 보실 곳 | 구현한 것 |
|---|---|---|
| ① 공통 사양 | 답변 아래 `원문 대조` | 근거를 찾아 답하고 답변의 쪽 번호와 수치를 원문과 대조 |
| ② 변종 구분 | 2단계 `변종 게이트` | CH334R을 물으면 CH334U 등 다른 변종 전용 청크 11개를 뺌 |
| ③ 없는 품번 | 4단계 `검증 게이트` | 문서에 없는 품번 CH999Z는 답을 만들지 않음 |
| ④ 없는 사양 | 5단계 `근거 충분성` | 품번은 맞지만 HDMI가 근거에 없어 모델을 부르지 않음 (토큰 0) |

이어서 위쪽 `modulino 부품 전체 (문서 5권)`을 누르고 `① 회로 기호`를 눌러 주세요. 0단계에서 회로 기호 U5를 BOM으로 품번(LMR33630)으로 바꿔 문서를 고르는 과정이 보입니다.

**2. `1부 검증 결과` 탭 (1분)**

맨 위 숫자 네 개를 보시면 됩니다. 다른 변종 청크 오통과 0건, 문서에 없는 질문 차단 10/10 등은 모두 스크립트 출력입니다. 아래에는 차단 기준값(2.5, 0.67)을 평가셋 38문항으로 정한 근거와 로컬 모델 2종의 비교가 있습니다.

**3. `2부 팀 운영`, `3부 문서 관리` 탭 (2분)**

각 폴더의 README와 같은 내용입니다. 3부는 `문서 관리 화면 열기` 버튼으로 실제 화면을 보실 수 있습니다.

## 직접 실행

새 질문을 직접 넣어 보시려면 GitHub 저장소를 받아 주세요. 전체 코드와 평가 기록이 있습니다.

https://github.com/hwy-10/lgd-ax-portfolio

1. 저장소 페이지에서 `Code` → `Download ZIP`

## 1. 데이터시트 검색

학부연구인턴에서 USB 허브보드를 설계하면서 만든 도구입니다. 이 보드는 허브 컨트롤러로 CH334U를 사용합니다. 회로 설계에는 동작 전압, 핀 배치, 패키지 같은 정확한 사양이 필요합니다.

CH334/CH335는 4포트 USB 2.0 허브 컨트롤러 계열입니다.

- 패키지: QSOP16 ~ LQFP48
- 기능: TT 방식, 과전류 검출, 전원 제어, LED 표시
- 품번 10종이 데이터시트 한 권(32쪽)에 함께 실려 있습니다

같은 표에서도 품번마다 값이 다릅니다. 패키지 표의 CH334R은 QSOP16이고 바로 아래 행의 CH334U는 QSOP28입니다.

언어모델은 근거가 부족하거나 다른 품번의 값이 섞여 있어도 그럴듯하게 답합니다(할루시네이션). 그래서 잘못된 근거로 답하지 않도록 검색기를 설계했습니다. 질문한 품번의 근거만 찾고 근거가 기준에 미치지 못하면 언어모델을 호출하지 않습니다.

| 검증 | 결과 |
|---|---|
| 다른 변종 청크 오통과 (게이트 통과 청크 1,000건 전수) | 0건 |
| 문서에 없는 질문 차단 | 10/10 |
| 기대 페이지 hit@5 | 28/28 |
| 부품 전체 확장 (데이터시트 5권, BOM 연동) 문서 선택 | 29/29 |

- 차단 기준: BM25 1위 점수 2.5, 질문 용어 등장 비율 0.67 (평가셋 38문항으로 결정)
- 전수 검사 품번 13종: CH334/CH335 변종 10종, 주변 부품 2종, 패키지 코드 1종

## 2. IDEC 팀 운영

IDEC 스마트 전자회로설계 챌린지 2인 팀의 작업 관리를 Plane으로 자동화했습니다. 팀 운영 규격을 직접 작성해 Claude에 지시문으로 제공했습니다. 그 결과 작업 51개가 모두 같은 형식과 숫자로 된 완료 조건을 갖췄습니다.

- 운영 규격: 작업종류 8종, 작업별 목표, 측정 가능한 완료 조건, 증빙 파일 경로, 설계 결정 기록, 되돌리기 어려운 6개 시점의 진행 기준
- 작업 51개, 완료 조건 280개, 증빙 파일 경로 178개, 설계 결정 28건
- 작업 목록은 스크립트로 Plane에 등록했고 등록 전에 "동작 확인" 같은 모호한 완료 조건이 없는지 검사했습니다
- 실행할 것은 없습니다. `02_idec_project/README.md`를 읽어 주시면 감사하겠습니다

## 3. 로컬 문서 관리

노션에서 쓰던 일정과 프로젝트 자료를 로컬 HTML 페이지로 옮겼습니다.

- 제출 페이지: 홈, 캘린더, IDEC
- 중간고사 대비 강의정리: 고급인공지능, 인공지능반도체설계, 반도체공학

같은 작업을 Claude에 시켜 호출 횟수와 주고받은 글자 수를 쟀습니다. 측정 방법과 조건은 `03_local_docs/README.md` 맨 위에 적었습니다.

| 작업 | 노션 API | 로컬 HTML |
|---|---|---|
| 일정 하나 추가 | 호출 6번, 약 15,000자 | 호출 3번, 약 1,500자 |
| 일주일 일정 읽기 | 호출 3번, 약 8,000자 | 호출 1번, 약 500자 |

혼자 관리하는 데 맞춘 구조입니다. 여러 사람이 함께 쓰는 데는 기존 플랫폼이 더 안정적입니다.

캘린더의 부족한 기능은 `03_local_docs/README.md`에 보완 계획으로 정리했습니다. 기능은 AI로 대부분 구현할 수 있어서 앞으로는 디자인을 공부해 원하는 화면을 구체적으로 설명하고 구현하려 합니다. AI에 모든 것을 맡기기보다 제가 아는 지식으로 AI를 최대한 활용하는 것이 목표입니다.
