## 1. 데이터시트 검색

학부연구인턴에서 USB 허브보드를 설계하면서 만든 도구입니다. 이 보드는 허브 컨트롤러로 CH334U를 사용합니다. 회로를 설계하려면 동작 전압, 핀 배치, 패키지 같은 사양을 데이터시트에서 정확히 찾아야 합니다.

CH334/CH335는 4포트 USB 2.0 허브 컨트롤러 계열입니다. 패키지(QSOP16 ~ LQFP48)와 기능(TT 방식, 과전류 검출, 전원 제어, LED 표시)에 따라 품번이 10종으로 나뉘며 데이터시트 한 권(32쪽)에 함께 실려 있습니다. 같은 표 안에서도 품번마다 값이 다릅니다. 패키지 표에서 CH334R은 QSOP16이고 바로 아래 행의 CH334U는 QSOP28입니다.

언어모델은 근거가 부족하거나 다른 품번의 값이 섞여 있어도 그럴듯한 답을 만들어 냅니다(할루시네이션). 그래서 잘못된 근거로 답하지 않도록 검색기를 설계했습니다. 질문한 품번에 해당하는 근거만 찾고 근거가 기준에 미치지 못하면 언어모델을 호출하지 않습니다.

| 검증 | 결과 |
|---|---|
| 다른 변종 청크 오통과 (게이트 통과 청크 1,000건 전수) | 0건 |
| 문서에 없는 질문 차단 | 10/10 |
| 기대 페이지 hit@5 | 28/28 |
| 부품 전체 확장 (데이터시트 5권, BOM 연동) 문서 선택 | 29/29 |

- 차단 기준은 BM25 1위 점수 2.5와 질문 용어 등장 비율 0.67이며 평가셋 38문항으로 정했습니다
- 전수 검사의 품번 13종은 문서에서 품번 형태로 인식되는 이름 전체입니다. CH334/CH335 변종 10종, 주변 부품 2종, 패키지 코드 1종입니다
- 직접 실행하는 방법과 필요한 설치 항목은 `01_datasheet_search/README.md`에 적었습니다

## 2. IDEC 팀 운영

IDEC 스마트 전자회로설계 챌린지 2인 팀의 작업 관리를 Plane으로 자동화했습니다. 팀 운영 규격을 직접 작성해 Claude에 지시문으로 제공했고, 그 결과 작업 51개가 모두 같은 형식과 숫자로 된 완료 조건을 갖췄습니다.

- 운영 규격: 작업종류 8종, 작업마다 목표와 측정 가능한 완료 조건과 증빙 파일 경로, 설계 결정 기록, 되돌리기 어려운 6개 시점의 진행 기준
- 작업 51개, 완료 조건 280개, 증빙 파일 경로 178개, 설계 결정 28건
- 작업 목록은 스크립트로 Plane에 등록했고 등록 전에 "동작 확인" 같은 모호한 완료 조건이 없는지 검사했습니다
- 실행할 것은 없습니다. `02_idec_project/README.md`를 읽어 주시면 감사하겠습니다

## 3. 로컬 문서 관리

노션에서 쓰던 일정과 프로젝트 자료를 로컬 HTML 페이지로 옮겨 사용하고 있습니다. 제출본은 홈, 캘린더, IDEC 세 페이지와 중간고사 대비 강의정리(고급인공지능, 인공지능반도체설계, 반도체공학)입니다.

같은 일정 하나를 Claude로 추가할 때 노션 API는 호출 6번, 약 15,000자를 주고받았고 로컬 HTML은 호출 3번, 약 1,500자였습니다. 일주일 일정 읽기는 노션 호출 3번, 약 8,000자에 로컬 호출 1번, 약 500자였습니다. 측정 방법과 조건은 `03_local_docs/README.md` 맨 위에 적었습니다. 다만 혼자 관리하는 데 맞춘 구조라 여러 사람이 함께 쓰는 데는 기존 플랫폼이 더 안정적입니다.

캘린더의 부족한 기능은 `03_local_docs/README.md`에 보완 계획으로 정리했습니다. 기능은 AI로 대부분 구현할 수 있어서 앞으로는 디자인을 공부해 원하는 화면을 구체적으로 설명하고 구현할 수 있게 하려 합니다. AI에 모든 것을 맡기기보다 제가 아는 지식으로 AI를 최대한 활용하는 것이 목표입니다.

`03_local_docs/index.html`을 열어 주세요.
